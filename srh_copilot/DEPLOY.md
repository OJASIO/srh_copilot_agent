# Hosting the prototype

This describes a **demo deployment**: a public URL you can send to a supervisor
or a teammate. It is deliberately not a production deployment, and the section
"Before real students use it" says exactly what is missing.

## Read this first: the free Gemini tier is not allowed to see real CVs

Google's [Gemini API Additional Terms](https://ai.google.dev/gemini-api/terms)
split the service in two. For **Unpaid Services** (the free key this project
uses) Google states that it uses submitted content to improve its products,
that human reviewers may read API input and output, and, verbatim:

> Do not submit sensitive, confidential, or personal information to the Unpaid Services.

A CV is personal data under GDPR. `cv_check/anonymiser.py` removes names,
contact details, addresses, birth data and personal details such as nationality or
religion before anything leaves the server, which is a real risk reduction, but
employers, dates, degrees and skill lists remain and are re-identifiable in combination.

So:

- **Test CVs written by the team: fine.** That is what this deployment is for.
- **Real student CVs: not on this key.** Moving to the paid tier changes the
  terms (Google does not train on paid-tier content) and is the prerequisite,
  together with a data processing agreement between SRH and Google, a documented
  retention period, and a privacy notice shown before upload.

The hosted UI shows a banner saying this, driven by the `DEMO_BANNER` variable.
Do not remove it while the deployment runs on a free key.

## Shape of the deployment

The platform gives one public port. Streamlit takes it; the API runs on loopback
inside the same container:

```
   browser  ->  :$PORT  Streamlit  ->  127.0.0.1:8000  FastAPI  ->  Gemini
```

`scripts/start_demo.sh` is the entrypoint: it rebuilds the vector index (about 55
chunks, a few seconds), starts the API, waits for `/health`, then starts the UI.

Nothing about the architecture changes. The frontend still reaches the API only
over HTTP through `COPILOT_API_URL`, so splitting them into two services is a
change to that one variable. The `Dockerfile` default command is still
API-only, which is what `docker-compose.yml` uses.

## Deploy to Render (free tier, no credit card)

1. **Push to GitHub.** `.env` is in `.gitignore`; confirm it is not in the
   repository before pushing:

   ```
   git status --porcelain --ignored | findstr .env
   ```

   `.env` must appear as ignored (`!!`), never as staged.

2. **Create the service.** On [render.com](https://render.com): New, then
   Blueprint, point it at the repository. `render.yaml` is picked up
   automatically.

3. **Answer the two secret prompts.**

   | Variable | Value |
   |---|---|
   | `GEMINI_API_KEY` | your key from [aistudio.google.com/apikey](https://aistudio.google.com/apikey) |
   | `DEMO_PASSWORD` | any phrase; visitors must type it before they see the app |

   `API_KEY` and `JWT_SECRET` are generated by Render and stay stable across
   deploys. Everything else is already in `render.yaml`.

4. **Wait for the first build** (a few minutes, mostly `pip install`). The URL
   is `https://srh-copilot.onrender.com` or similar.

5. **Check it.** Open the URL, enter the password, pick Student Service, and try
   both tasks. `GET /health` is not public in this layout; the container's own
   health check uses Streamlit's `/_stcore/health`.

### What the free tier costs you

- 750 instance hours a month, which is enough for one service.
- The instance **sleeps after 15 minutes without traffic** and takes up to a
  minute to wake. The first visitor after a quiet period sees a loading page.
  `fetch_agents()` retries for about 30 seconds to cover the API starting behind
  the UI.
- **No persistent disk.** The vector index is rebuilt at every start, which is
  why ingestion is in the entrypoint. Conversation history is in memory and is
  lost on restart, as `VECTOR_BACKEND=memory` implies.
- Render may restart free services without warning.

Tell your supervisor to expect the first click to be slow. Opening the link a
minute before a meeting warms it up.

## Alternatives, and why not

| Option | Verdict |
|---|---|
| Hugging Face Spaces | Docker Spaces now require a PRO account for personal use. Free accounts get Gradio ZeroGPU Spaces only. Out. |
| Google Cloud Run | Technically the best fit: Frankfurt region, scales to zero, generous always-free allowance. Needs a billing account with a card, so it was ruled out here. Revisit when moving to the paid Gemini tier, since that needs billing anyway. |
| Streamlit Community Cloud | Free and reliable, but it runs one Streamlit process. The API would have to be started inside it in a thread, which collapses the two-tier architecture the case study is about. |
| University infrastructure | The correct answer once real students are involved. Start that conversation early; it is slower than any of the above. |

## Environment variables

| Variable | Purpose | Demo value |
|---|---|---|
| `GEMINI_API_KEY` | LLM and embeddings | your key, secret |
| `DEMO_PASSWORD` | shared password gate on the UI | any phrase, secret |
| `DEMO_BANNER` | warning shown above the chat | set in `render.yaml` |
| `API_KEY` | frontend to API shared key | generated by Render |
| `JWT_SECRET` | signs user tokens | generated by Render |
| `APP_ENV` | `dev` here on purpose, see below | `dev` |
| `RATE_LIMIT` | per-IP request cap | `20/minute` |
| `PORT` | public port, set by the platform | injected |
| `API_PORT` | loopback port for the API | `8000` |

`APP_ENV` stays `dev` because `Settings.assert_production_safe()` refuses to
start in `prod` with `VECTOR_BACKEND=memory`. That check is correct and should
not be weakened: this deployment genuinely is not production.

## Before real students use it

In rough order of importance:

1. **Paid Gemini tier**, plus a DPA and a privacy notice at the upload step.
   Everything else is pointless without this.
2. **Real authentication.** The demo password is one shared phrase and the
   sidebar user picker issues any role on request. Replace with university SSO
   (Entra ID / OIDC) and enforce roles in `Retriever.search` for staff-only
   collections.
3. **Postgres and pgvector** (`VECTOR_BACKEND=pgvector`, `docker-compose.yml`
   already defines it) so sessions and the index survive restarts, plus Alembic
   migrations.
4. **Retention.** Uploaded CVs are currently held only in memory for the
   duration of the request, which is good. Keep it that way, and write it down.
   The audit trail in `SessionStore.audit` stores messages; decide a retention
   period and redact.
5. **A paid instance** so it does not sleep, and a region inside the EU.
